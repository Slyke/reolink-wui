# Compatibility

Capabilities describe a specific camera/channel as reported by the bridge. Model names alone do not enable controls. Availability and freshness gate writes. Monitor shows detections retained by the WUI. After a bridge disconnect, it refreshes state and marks the gap.

| Model / revision / firmware | Feature | Transport | Evidence and limits |
| --- | --- | --- | --- |
| Standalone cameras with the bridge's Baichuan capability discovery | PTZ reads, bounded moves, Stop, presets, zoom; spotlight, LED, motion and AI settings | HTTP, WS, or MQTT 5 for supported typed commands | Exercised against the bridge's mock camera and local broker. Each operation and native range comes from the channel's capabilities. |
| Baichuan capture support | PNG snapshot and download | MQTT 5 | Bridge capture is limited to 1920×1080 and the broker's packet budget. WUI validates the decoded PNG; downloads use a short lived browser object URL. |
| Cameras with ONVIF or Baichuan event coverage | Availability, detections, rule snapshots and object metadata | WS or MQTT 5 | The bridge chooses device protocols. Rule schedules, zones and camera-owned actions beyond current motion/detection operations have no verified write path. |
| Any configured bridge with WUI v1 and supported Baichuan settings | Fresh LED, spotlight, motion and AI readback | Private HTTPS | A fresh read is required after an uncertain settings write. PTZ uses a fresh position read. Legacy retained snapshots alone cannot clear a write fence. |
| Lumus E430, hardware `IPC_NT1NO24MP`, firmware `v3.1.0.6198_2604102075` | Wi-Fi join QR, factory password and credential rotation protocol | Browser-only QR and private Baichuan | The sibling provisioning CLI previously verified Wi-Fi QR and first-password setup. The WUI port is tested with a mock. A new hardware or firmware combination stays unsupported until verified. |
| E1 Pro E330, hardware `IPC_NT1NA45MP`, firmware `v3.1.0.4417_2412122130` | First admin password via Enrollment | Private Baichuan over Ethernet | A factory camera supplied its firmware, UID and factory administrator list. A simulated camera exercises the password change, verified login, retry and activation of the configured camera without a second restart. |
| Other powered Wi-Fi, PoE, or Ethernet devices | Enrollment by verified UID or reported hardware serial | Private Baichuan | Configure the target on the bridge. Use Reolink Client locally for unsupported initialization, then import a private credential. PoE and Ethernet enrollment use the LAN. |
| Native channel overlays | Watermark, text background, name and timestamp | Bridge HTTP API over Baichuan | Saves preserve both channel overlay blocks and verify the edited fields. A refusal identifies the requested settings and, on newer bridges, the camera’s native status. |
| Camera with a third native live profile | Third stream in Live view | Bridge HTTP relay over camera Baichuan | Enable `third` in `api.media.<camera>.streams` with `auto` or `baichuan` transport. Lumus E430 returned 896 × 512 from this profile. The camera supplies any editable encoder settings separately. |
| Explicitly configured RTSP H.264 main or substream | Live relay | Private RTSP/TCP to bridge, multipart MJPEG from WUI | Video-only fallback for browsers that cannot play device RTSP. Configuring a profile is a deployment assertion; verify it for the specific camera and profile before advertising it. Relays expire within two minutes and close on grant/session revocation. |
| Configured Frigate or compatible RTSP restream | Dashboard preview and continuous playback | Private RTSP/TCP to WUI, JPEG or multipart MJPEG to browser | Select the per-camera RTSP proxy source. The WUI API runs FFmpeg and closes live streams on source change, expiry, or grant revocation. |
| Browser-to-camera media | Requires verified device playback authorization | — | The device would need playback-only credentials with an enforceable short expiry. |
| Cameras with saved JPEG time lapses | Timeline hover and touch scrubbing | Bridge time-lapse photo gallery | The nearest saved capture is available on photo-only days and between video clips. Viewing requires the recording-view grant. Full-resolution ZIP downloads also require export access. |
| Cameras with bridge native recording support | SD-card usage, combined quality search, timeline thumbnails, recording metadata and MP4 playback | Private bridge HTTP(S) API | Native downloads, 300/331 completion, cached previews, conversion and byte ranges are tested against a synthetic camera. WUI playback, preview grants, layouts and end modes are browser-tested. |
| Cameras reporting orientation capabilities | Horizontal/vertical flip and clockwise/counterclockwise 90° rotation where supported | Private bridge HTTP(S) or MQTT commands | Writes and readback are tested on a synthetic camera. A Lumus read reported flips with no rotation value; unsupported controls stay disabled. |
| Recording exports | Per-camera recording export grant | Camera recording and gallery support | |
| Camera speaker | Hold **Hold to talk** in Live view over HTTPS or localhost | `audio.talk` grant, bridge `talk` capability and supported mono ADPCM | Releases on button-up, modal close or stream timeout |

The default QR for device identification is the WUI format (`REOLINK-WUI/1`, separate UID and serial fields). For Wi-Fi on the documented revision the join QR is a separate, in-browser artifact. No vendor enrollment QR is emitted for an unverified identifier format. See the [Reolink setup guide](https://support.reolink.com/articles/360020094714-How-to-Initially-Set-up-Reolink-WiFi-Cameras-without-LAN-Port-via-Reolink-App/) and [Reolink's RTSP notes](https://support.reolink.com/articles/900000630706-Introduction-to-RTSP/).

**Wired setup for Wi-Fi cameras.** Reolink documents optical QR setup on E330 units, and also offers Bluetooth setup on some E1 Pro/E330 revisions. The WUI optical format was tested on the Lumus E430. For a supported factory camera on Ethernet, put its wired IP and desired admin password in its `cameras[]` entry and enable the bridge credential vault (`api.storageDirectory`). In **Settings → Enrollment**, choose the bridge and **Set first admin password**. Enter the IP, optionally enter its Baichuan port, and select **Identify camera**. Check the reported UID against the camera label and confirm **Start enrollment**. The bridge sets the password and activates the configured camera in the same process. Older bridge releases use named enrollment targets. Other revisions can use private credential import after local initialization. Open **Settings → Camera settings → Network and Wi-Fi** and save the target SSID and password. When switching interfaces, look up the camera’s wireless DHCP lease and update its bridge host if needed. On models that mask their saved key, the WUI reports how much it could verify.
